## Delegation

- The parent agent writes and edits all documentation. Subagents provide findings and implementation details for the parent to document.
- Give each subagent the objective, relevant context, owned files, and expected deliverables.
- Provide a task-specific, numbered plan in dependency order, with a concrete action and expected result for each step.
- Include completion checks. Keep the plan proportional to the task and leave routine implementation choices to the subagent.

## Writing Style

Apply these rules to responses and documentation.

- Lead with the main point. Describe current functionality and behavior directly in plain, concise language.
- Address the user's actual request. Do not invent an expectation, objection, or alternative to rebut.
- Do not decline or redirect work based on an assumed blocker. Check the relevant facts first; if a concrete blocker remains, state it and complete the feasible part.
- Include a caveat only when it materially changes the requested result or the user's immediate decision. State the relevant fact directly, without a preemptive contrast.
- Before sending a response or publishing documentation, remove unsolicited disclaimers and statements about unrelated work not done, unchanged behavior, or compliance with instructions.
